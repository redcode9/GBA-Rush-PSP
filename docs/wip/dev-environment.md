## Note dell'ondata del 2026-11-04

- **Scelte rispetto al testo dei ticket.** `scripts/fetch-test-roms.sh` di ENG-10.4 è il passo `test-roms` di `scripts/setup-dev.sh`, in `ext/test-roms/` invece di `build/test-roms/`. `tests/test-roms/THIRD-PARTY.md` non esiste: la regola del repository vieta file markdown nuovi, quindi fonte, commit, licenza e uso di ogni suite stanno nell'intestazione di `setup-dev.sh`. armwrestler-gba-fixed non dichiara una licenza: si usa solo in locale e nulla di derivato entra nel repository.
- **Versioni fissate.** pspdev v20260801 (sha256 dei tarball per macOS arm64 e x86_64, Linux x86_64 e arm64; quello per macOS arm64 coincide con `~/Development/.tools/pspdev-v20260801-arm64.tar.gz`), Arm GNU Toolchain 15.2.Rel1 (solo macOS arm64), Unicorn 2.1.4 (sha256 del tarball in `build-unicorn.sh`), mGBA 0.10.3 (1c61b54), SingleStepTests ARM7TDMI (e3097d8), gba-tests (a7113b6), armwrestler-gba-fixed (802e55a), FuzzARM (a675329), suite di mGBA (e694203), PPSSPP v1.20.4 (fa50bb1). I sorgenti Git sono fissati per commit.
- **Riuso.** `setup-dev.sh` collega in `ext/` il pspdev di `PSPDEV` o `~/Development/.tools/pspdev`, l'arm-none-eabi-gcc nel PATH o arm-gcc-bin@15 di Homebrew e l'Unicorn di `UNICORN_DIR` o di Homebrew; costruisce Unicorn con le patch Allegrex solo se non ne trova uno.
- **Verificato qui.** `make check` con un PATH senza `rg` e senza `psp-config` (messaggio che indica `setup-dev.sh`), e con lo SDK; `--dry-run` su questa macchina e simulando una macchina pulita; seconda esecuzione che non rifà nulla; sha256 sbagliato che ferma lo script (prova su un file locale); `make psp-build` con le variabili stampate dallo script; `check-core --quick` con l'Unicorn di Homebrew; `check-eboot` con un finto PPSSPP (layout, cartelle, file di impostazioni per i due core, salvataggio rovinato che fa fallire).
- **Misure.** Con l'Unicorn di Homebrew, senza patch, il fuzzer del backend impiega 0,9 s per 5 casi, 181 s per 20 casi e oltre 28 minuti per i 200 casi predefiniti di `make check-core`: per la CI conviene l'Unicorn con le patch (`build-unicorn.sh`) o pochi casi. Le versioni rapide usano 5 casi, i primi 1000 test di ogni file di SingleStepTests, 60 frame di lockstep per gioco (da tarare sulla riga «instructions compared» per arrivare a circa un milione di istruzioni) e 300 frame di render per gioco; senza giochi il render prende le ROM di prova libere di gba-tests (`tests/render/still.txt`), così il job CI ha qualcosa da confrontare.
- **check-eboot da tarare.** Una corsa riesce se PPSSPP arriva al timeout (`TIMEOUT` nel suo output) senza parole come «exception» o «crash», e se il salvataggio di FireRed tiene la stessa squadra. Non è stato possibile provare con PPSSPP quale cartella vede l'EBOOT (argv[0] fuori da ms0:) né che cosa stampa un crash: alla prima esecuzione vanno controllati `build/eboot/*/ppsspp.log`. `exception.prx` resta fuori di proposito, perché la schermata di crash aspetterebbe un tasto.
- **Correzione trovata.** `tests/core/single_step.c` non compilava senza Unicorn (`cycles` inutilizzata con -Werror): check-core falliva su SingleStepTests appena `UNICORN_DIR` mancava. Corretto.
